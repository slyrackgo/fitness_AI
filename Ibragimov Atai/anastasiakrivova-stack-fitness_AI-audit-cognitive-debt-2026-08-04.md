### Расчёт оценки

Оценку повышают явная цель в README и согласованность состава сервисов с маршрутами; сильнее всего её снижают отсутствие контекстного файла для агентов и почти полное отсутствие исполнимых спецификаций. Взвешенный расчёт: `4×25% + 2×20% + 3×20% + 0×10% + 5×25% = 3,25 из 10`, то есть 32,5%, округлённые до **33/100**; ограничивающие пороги не применялись.

Уверенность средняя. Оценены все пять измерений по доступному репозиторию; внешние системы не исключались из расчёта и не штрафовались. Уверенность ограничивают поверхностная история, отключённые Issues, пустая доступная выборка pull request и отсутствие обнаруженных внешних продуктовых документов.

### Карта замысла

- Цель: `README.md:13` описывает backend микросервисов для масштабируемой модульной фитнес-платформы.
- Ограничения: gateway публикует `/api/users/**`, `/api/activities/**` и `/api/recommendations/**`; Activity Service проверяет `userId` до сохранения; Activity Service и AI Service связаны через RabbitMQ.
- Предметные правила: тип активности ограничен перечислением, а AI-рекомендация ожидает поля `analysis`, `improvements`, `suggestions` и `safety`.
- Решения: rationale микросервисного разделения, RabbitMQ, хранилищ и формы AI-контракта не оформлено в ADR или журнале решений.

### Исполнимый замысел

Код реализует проверку пользователя, сохранение активности, публикацию события, генерацию рекомендации и fallback при ошибке AI-ответа. Найденные тесты проверяют только запуск Spring-контекста; API-контракты, event flow, JSON-формат и safety fallback не доказаны тестами или примерами.

### Восстановление понимания

Новый участник может реконструировать общую архитектуру, последовательно читая несколько модулей. Неочевидные причины и компромиссы восстановить нельзя: нет ADR, архитектурной карты, глоссария, индекса документации, содержательной истории обсуждений или инструкции для агентов.
