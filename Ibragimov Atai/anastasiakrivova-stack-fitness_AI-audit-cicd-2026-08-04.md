# Аудит CI/CD: anastasiakrivova-stack/fitness_AI

## Краткое резюме

- Основная ветка и путь поставки сейчас не защищены: CI/CD-пайплайн — автоматический путь проверки изменений — отсутствует, `master` не защищена, а выпуск и откат не автоматизированы.
- Репозиторий имеет полезную основу для CI/CD: Maven Wrapper, `pom.xml`, команды сборки и тесты для четырёх Spring Boot-модулей. Это не полное отсутствие инженерной дисциплины, но проверки пока остаются ручными и разрозненными.
- Итоговая оценка — **9 из 100**, уровень `bad`, уверенность высокая. Отсутствие CI подтверждено файлами репозитория и пустой историей GitHub Actions; состояние защиты ветки подтверждено данными GitHub.
- Лучший следующий шаг — дать разработчикам одну команду проверки из корня, затем добавить базовый GitHub Actions для pull request и `master`, стабилизировать его и сделать обязательным барьером перед слиянием.

## Что было проверено

Проверены конфигурации CI/CD, триггеры и задания, история GitHub Actions, защита `master`, локальные команды сборки и тестов, создание артефактов — результатов сборки, например jar-пакетов или образов, — а также автоматизация релиза, деплоя, продвижения и отката. Репрезентативные пути: `README.md`, четыре `pom.xml`, Maven Wrapper в `eureka/eureka`, `userService`, `activityService/activityService` и `AI_Service/AI_Service`.

Контейнерные файлы не найдены, поэтому интеграция контейнеров признана неприменимой и не снижает оценку. Проектный `GUARD.md` или отслеживаемый `ENJI_GUARD.md` отсутствует, поэтому дополнительных проектных указаний, меняющих область или выводы аудита, не было.

## Находки

### Основной ответ
> [!CAUTION]
> **Вопрос аудита:** Насколько текущий процесс CI/CD защищает основную ветку и путь поставки от непроверенных изменений и какая последовательность следующих шагов сделает его надёжным?
>
> **Ответ:** Практически не защищает, с высокой уверенностью: CI/CD отсутствует, `master` не защищена, а обязательного барьера — проверки, способной остановить плохое изменение, — нет. Надёжность следует наращивать по порядку: единая локальная команда, валидный CI, реальные проверки, обязательная блокировка слияния, дополнение проверок, стабилизация, затем автоматизация артефактов, релиза, деплоя и отката.

### Расчёт оценки

Оценку главным образом повысили воспроизводимая локальная Maven-основа и возможность собирать jar-файлы. Сильнее всего её снизили полное отсутствие CI, незащищённая `master`, разрозненный вход для модулей и отсутствие автоматизации поставки. Компактный расчёт: сумма критериев `19/60` даёт `round(19 ÷ 60 × 100) = 32`; вычеты `20 + 3 = 23`, а ограничение для активного репозитория без CI равно `39`, поэтому `min(32 − 23, 39) = 9`.

### Ключевые находки

| Находка | Влияние | Уверенность | Доказательство | Следующее действие |
|---|---|---|---|---|
| CI/CD отсутствует для активных backend-сервисов | Критическое: изменения могут попасть в `master` без сборки и тестов | Высокая | Нет `.github/workflows/`; история GitHub Actions пуста; `master` не защищена | Добавить CI для pull request и push в `master`, запускающий проверки всех подтверждённых Maven-модулей |
| Нет единого входа для проверки репозитория | Среднее: будущий CI сложнее повторять локально и поддерживать | Высокая | Четыре отдельных `pom.xml`; README начинает сборку с ручного перехода в модуль; у `configServer` и `gateway` нет `pom.xml` | Зафиксировать охват модулей и добавить корневой скрипт либо parent Maven project |

## Доказательства

- `.github/workflows/` и конфигурации других распространённых CI/CD-систем не обнаружены; история GitHub Actions содержит ноль запусков.
- GitHub сообщает для `master` значение `protected=false`; `CODEOWNERS` не найден. Дополнительные rulesets отдельно не проверялись.
- В `eureka/eureka`, `userService`, `activityService/activityService` и `AI_Service/AI_Service` присутствуют `pom.xml`, Maven Wrapper версии `3.9.11` и стандартные Spring Boot тесты.
- `README.md` описывает ручную сборку и запуск jar-файлов; автоматическая публикация артефактов, релиз, деплой, продвижение и откат не обнаружены.
- В `configServer/configServer` и `gateway/gateway` исходники есть, но `pom.xml` в проверенном срезе отсутствует, поэтому их поставка не подтверждена.

## Ограничения

- Maven-команды не запускались; их доступность оценена по документации, `pom.xml`, wrapper-файлам и тестовым исходникам.
- Внешние среды и ручные процедуры, не отражённые в репозитории, недоступны наблюдению.
- Дополнительные GitHub rulesets не проверялись, хотя флаг защиты ветки `master` доступен и равен `false`.
- История Git неглубокая, поэтому аудит описывает состояние указанного коммита, а не эволюцию процесса.
- Проектный Guard-контекст отсутствует; это нейтрально и не влияло на оценку.
- Сопоставимый предыдущий аудит недоступен, поэтому этот результат становится исходной точкой для следующего сравнения.
